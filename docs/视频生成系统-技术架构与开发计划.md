## 一、系统目标

构建一个 agent 驱动的可编程视频生成系统：

- **多源输入**：提示词、网页 URL、图片、文档等资源；
- **四阶段流水线**：特征描述文件（spec）→ 素材生成 → 录音/字幕 → 视频合成；
- **技能可注入**：在提示词或消息体中声明技能（three.js 特效、图表、代码动画等）；
- **元素级可控**：字体、颜色、风格、素材、特效全部由结构化 spec 精确控制，可复现、可微调、可重渲染。

**通用性定位（v1.4）**：系统面向**通用视频生成**——科普、教学、营销、资讯等任何"分镜 + 口播"型视频。核心链路（DSL schema、parser、Scene/布局组件、渲染管线、四阶段编排）**不含领域假设**；DSL 的场景枚举是通用讲解结构（开场/问题/概念/公式/图表/结论……），天然跨领域。领域差异封装为**领域包** = 主题色卡 + 场景模板/蓝图 + 领域技能包：量化科普是**首个领域包**（因其 DSL 资产最成熟），后续新领域只需新增领域包并在 spec 中选用主题与技能，核心代码零改动；无领域包时以内建默认主题兜底。

核心设计原则：**LLM 负责创作，代码负责保真。** 模型不直接生成视频，而是生成一份强校验的 spec；渲染层（Remotion）严格按 spec 逐帧执行。

## 三、核心设计：YAML 描述文件是唯一事实源

> ⚠️ **资产状态警示（v1.3）**：本节引用的四份资产——`concept-video-dsl.md`（v3.0）、`concept-video-scene-templates.yaml`（v2.1）、`量化色卡规范.md`、`skills/quant-video-remotion/`——**经核验不在 DeepTutor 仓库中**。若它们存在于其他机器/仓库，须在 G0 门禁（§九）前取回并入库；若不存在，本节即转化为**建设规格**，按 §九路径 B 从零建设。下文表述沿用"已有资产"口径，阅读时请注意此前提。

**格式决定：视频描述文件使用 YAML**，并直接采纳已有的《量化科普概念讲解视频 · 数据 DSL 标准》（`concept-video-dsl.md` v3.0）作为权威契约，不另行发明 schema。三层契约分工（与现有资产一一对应）：

| 层 | 资产 | 职责 |
|---|---|---|
| 数据契约 | `concept-video-dsl.md`（v3.0） | **说什么、什么数据**：13 种场景类型 + PageModel + JSON Schema |
| 页面蓝图 | `concept-video-scene-templates.yaml`（v2.1） | **每屏怎么布**：layout / elements / regions / narration 指导 |
| 视觉权威 | `量化色卡规范.md` + `skills/quant-video-remotion/` | 内建主题色板（v3.1 起允许 YAML `style.colors` 重定义 token 值）/ 组件 / 渲染流程 |

spec 文件形态（命名 `data/videos/<series_slug>_ep<NN>.yaml`，UTF-8，2 空格缩进，禁 Tab）。**颜色、风格、字体、特效、分镜全部写入同一份 YAML**——其中分镜（`scenes`）是 DSL v3.0 已有能力，设计层（颜色/字体/风格/特效）以 **DSL v3.1 扩展提案**的 `style` 块承载：

```yaml
version: "3.1"
series: 量化科普
episode: 3
fps: 30                       # 枚举 24/25/30/60

# ═══ 设计层（v3.1 新增）：一份文件装下全部视觉决策 ═══
style:
  theme: quant-traditional    # 基础主题（色卡规范的内建主题）
  preset: tech-minimal        # 风格预设（可选，影响留白/圆角/动效强度）
  colors:                     # token 覆盖（可选）：hex 唯一合法出现处
    primary: "#1A5FB4"        #   仅允许重定义 7 个枚举 token 的值
    danger:  "#D64545"        #   场景内引用仍是 token，禁裸 hex
  fonts:
    title:  { family: "Noto Sans SC", weight: 800 }
    body:   { family: "Noto Sans SC", weight: 500 }
    number: { family: "JetBrains Mono", weight: 600 }   # 数字/公式/代码
  effects:                    # 全局特效默认值
    transition: { type: fade, frames: 15 }      # 场景间转场
    entrance: fadeIn                            # 元素默认入场
    chart_motion: drawLine                      # 图表动效
    background: { type: none }                  # none | gradient | 特效技能

opening:
  title: "最大回撤是什么？"               # ≤14 字
  subtitle: "为什么同样赚30%体验天差地别"  # ≤20 字

# ═══ 分镜层（v3.0 已有）：13 种场景枚举 × PageModel ═══
scenes:
  - type: problem_hook        # 封闭 13 种场景枚举
    layout: split             # 24 种布局枚举（layout_library）
    style:                    # 分镜级覆盖（可选）：优先级高于全局 style
      colors: { primary: danger }              # token 重映射（值仍是 token）
      effects:
        transition: { type: wipe-left, frames: 20 }
        background: { type: particles, skill: three/particle-wave,
                      params: { count: 5000, color: primary } }   # 特效技能注入点
    # ── PageModel 六字段，每屏必填 ──
    title: 同样赚30%为何体验不同
    question: 什么拉开持有体验？
    core_message: 差距往往在最大回撤，而非收益率   # ≤120 字，一页一结论
    narration:                # 三段式 → 直接作为 TTS 输入
      { opening: "", explanation: "收益相同不代表体验相同。", conclusion: "看回撤。" }
    visual: { primary: 两条资金曲线, secondary: 关键词高亮, emphasis: 深度下跌区 }
    transition: { next_question: "回撤到底怎么衡量？" }
    # ── 类型专有 content_slots ──
    phenomenon: "两个策略都赚了 30%，一个能长期持有，另一个却可能让你中途崩溃离场。"
    counter_question: "真正拉开差距的，为什么不是收益率？"
    promise: "这期讲清最大回撤。"
```

**样式解析链（renderer 合并规则）**：

```
内建主题（色卡规范） → style.theme 选择 → style.colors 覆盖 token 值
  → 分镜 style.colors 重映射 → 组件最终取色
字体：style.fonts（全局） → 分镜可覆盖 → 组件 typography 默认值兜底
特效：style.effects（全局默认） → 分镜 style.effects 覆盖 → 元素 animation 兜底
```

设计要点：

- **封闭枚举即可控性**：场景 13 种、布局 24 种、颜色 7 个枚举 token、图表 7 种、转场/动效枚举——LLM 的自由度被约束在枚举与字数限制内。**v3.1 的唯一开口**是 `style.colors` 允许写 hex，但它只能**重定义 token 的值**（相当于在文件内自定义色卡），场景内依然只能引用 token——既满足"颜色写进 YAML"，又不破坏"禁裸 hex"的纪律；
- **一页一文件全知**：颜色、字体、风格、特效、分镜、口播、数据全部在同一份 YAML，改任何维度都是改文件 → 局部重渲染；文件可直接进 git 做版本管理与 diff 审阅；
- **PageModel 六字段每屏必填**（title/question/core_message/narration/visual/transition），制度上保证"一页一个核心结论"；`narration` 三段式天然成为 Stage 3 的 TTS 输入；
- **YAML 是正确选择**：LLM 生成 YAML 的容错率优于 JSON（无引号配平/尾逗号问题）、人类可读可批注、支持注释与多行文本；YAML 解析后直接用 JSON Schema（draft 2020-12）机器校验——**生成与校验解耦**；
- **每支视频 = 骨架复制 + 槽位填充**：按长度预设（7/10/13 屏，DSL §7）复制 `video_blueprint`，LLM 仅填 style + PageModel + content_slots，布局与元素从模板库继承——生成稳定性远高于自由编排，这也回答了"spec 复杂度爆炸"的风险。

**DSL v3.1 扩展提案清单**（需落到 `concept-video-dsl.md` 升版）：

| 扩展点 | 内容 |
|---|---|
| 顶层 `style` 块 | theme / preset / colors / fonts / effects 五字段，全部可选 |
| 分镜级 `style` | 场景内同名子集，合并优先级高于全局 |
| JSON Schema 增补 | §10 增加 `style` 定义：`colors` 仅允许 7 个 token 键、值为 hex 格式；`fonts.family` 走字体白名单；`effects.transition.type` 枚举（fade/wipe-left/slide/zoom/none）；`background.type` 枚举 + `skill` 引用已安装技能 |
| parser 变更 | §11 IR 增加 `StyleChain`；§12 渲染映射不变（样式经 theme provider 注入，组件零改动） |
| 向后兼容 | v3.0 文件无 `style` 块 → 全部取内建主题默认值，行为不变 |

## 四、流水线详细设计

### Stage 0 · 端到端编排（Capability: `video_pipeline`，v1.3 新增）

DeepTutor 的 capability 各自拥有一个 turn，四阶段不会自动串联。`video_pipeline` 是用户"一句话出片"的入口：

1. 接收用户意图（提示词/URL/附件 + 可选风格声明）；
2. 依次调度 `video_spec → asset_gen → narration_gen → video_compose`，每阶段产物落盘后才进入下一阶段（产物即契约，阶段间不共享内存状态）；
3. 任一阶段失败时，从断点阶段重跑（YAML 与产物目录是唯一状态，天然可续跑）；
4. 用户也可绕过 Stage 0，单独触发任一阶段 capability（改字重渲染、只重配音等局部迭代场景）。

### Stage 1 · 描述文件生成（Capability: `video_spec`）

| 项 | 设计 |
|---|---|
| 输入 | 提示词 / 网页（复用 `web_fetch`）/ 图片与文档（复用附件解析、MinerU 等文档解析层）/ 既有 CSV 数据 |
| 过程 | ① 按意图选长度预设（7/10/13 屏，`ask_user` 澄清受众与风格偏好：主题/主色/字体/特效）→ ② LLM 先生成 `style` 设计块（颜色 token 覆盖、字体、全局特效），再以**场景模板库 + DSL 字段约束**为上下文逐屏填充 PageModel + content_slots（含分镜级 style 覆盖）→ ③ YAML 解析后经 DSL §10 JSON Schema（含 v3.1 style 定义）机器校验，再按 §13 清单做语义复查（如"每个 formula 必配 numeric_example""conclusion 恰好 3 卡"），不通过则带错误回炉 |
| 输出 | `data/videos/<series_slug>_ep<NN>.yaml`（人类可直接编辑） |
| 复用 | DeepTutor 的 capability 模式、agent loop、`ask_user`；**模板库即生成护栏，无需自研**（前提：G0 门禁通过，见 §九） |

### Stage 2 · 素材生成（Capability: `asset_gen`）

| 素材类型 | 来源 |
|---|---|
| 插画/配图 | `imagegen` 工具（Settings 配置生成模型），产物落配套 `assets/` 并在 YAML 中引用 |
| 网页/文献素材 | `web_fetch` + 截图。**注意（v1.3）**：runner 沙箱镜像（`Dockerfile.runner`）当前无 headless browser，需在 runner 镜像加装 Chromium + Playwright，属新增工作（见 §六） |
| 图表数据 | 用户 CSV / 接口数据，落 `data/` 供 `chart_verification.data` 外链（DSL 规定路径相对 `data/`） |
| BGM/音效 | 本地素材库 |

每个素材生成后记录生成参数（prompt、模型、种子）到旁车 `.meta.json`——保证可复现。注意：DSL 的颜色由 theme 与色卡 token 保证，素材生成 prompt 需注入主题色板描述以保持视觉一致。

### Stage 3 · 录音与字幕（Capability: `narration_gen`）

1. 逐屏取 `narration.{opening, explanation, conclusion}` 拼接为该屏口播稿，调用 TTS provider（复用 DeepTutor Settings 的 TTS/STT 配置层）逐屏生成音频；
2. **时间戳对齐**：沙箱内跑 whisperX 得到词级时间戳。**注意（v1.3）**：whisperX 不在 runner 镜像内，需随镜像加装（与 Stage 2 的 Chromium 同属 runner 镜像扩展项）；
3. 回写产物目录：每屏得到真实音频时长与词级时间戳（`audio/s<NN>.align.json`），字幕轨生成 `cues: [{start, end, text}]`；
4. **时长覆盖语义（v1.3 明确）**：真实音频时长**在渲染层 IR 注入期覆盖** DSL 的 `duration_frames` 默认值（读取 `.align.json` 注入），**不回写 YAML**——YAML 保持纯创作层，重配音不改变事实源文件，git diff 干净。

### Stage 4 · 视频合成（Capability: `video_compose` → remotion-worker）

```
FastAPI ──POST /render {yaml_path, job_id}──▶ remotion-worker (Node)
                                                 │
                    ┌─ YAML → parser（按 DSL §10 JSON Schema 校验，ajv）
                    │     → 规范化 TS IR（DSL §11：默认值注入 / 布局别名解析
                    │        / .align.json 时长覆盖 ← Stage 3 产物）
                    │     → Scene 组件（DSL §12 渲染映射表）
                    │     → layout → src/layouts/ 24 种布局组件
                    │     → 公式 KaTeX 渲染 / 算例 Math.js 实时计算
                    │     → 字幕轨（Stage 3 对齐结果）+ BGM 混音
                    └─ headless Chrome 逐帧 → ffmpeg → renders/<job_id>.mp4
                                                 │
FastAPI ◀──WS 进度事件 / 完成回调──────────────────┘
```

- **渲染契约**：DSL `type` → 场景组件、`layout` → `src/layouts/` 布局组件（DSL §12 / §12.x 映射表，外层统一 `SceneFrame` 标题条 + 字幕 + 风险条）——你已有的 parser 契约直接复用（前提同 G0 门禁）；
- **样式注入**：parser 输出的 IR 携带样式链（内建主题 → `style.theme` → `style.colors` → 分镜覆盖），经 theme provider 注入组件树，组件零改动；字体随镜像分发并在渲染前注册到 Chromium；
- **three.js 特效**：通过 `@remotion/three`（React Three Fiber）实现，作为新场景/元素类型注册进映射表，`params` 即组件 props；
- **局部重渲染**：修改单屏时只渲染该屏帧区间再拼接（Remotion 支持 `--frames`），大幅缩短迭代周期；
- **预览**：前端嵌入 **Remotion Player**，直接执行"YAML → parser → IR"喂给 Player——spec 修改即时预览，无需等待完整渲染，这是选型 Remotion 的最大交互红利。**注意（v1.3）**：前端当前无任何 Remotion 依赖（`web/package.json` 已核验），Player 预览页与 parser 的 TS 移植均为纯新增工作量，勿计入"复用"。

## 五、技能系统设计（注入机制）

**`skills/quant-video-remotion/` 规划为第一个领域技能包**——它内含 references（组件、渲染管线、视觉规范），结构上正是 DeepTutor SKILL.md 规范的预期形态（参照 `deeptutor/skills/builtin/` 现有 5 个内建技能），直接挂载即可，无需改造（前提：G0 门禁取回该资产）。技能注入的三个面：

1. **提示词注入**：用户在消息里声明（"用粒子波浪做开场""这期讲夏普比率"）→ `video_spec` capability 检索已安装技能 → 把技能的约束文档（模板库/色卡/组件清单）注入 LLM 上下文 → 产出符合 DSL 的 YAML；
2. **项目级挂载（v1.3 修正）**：DeepTutor 的 sticky 会话上下文**只支持 subagent / KB / persona / model / voice，不含技能**；技能侧现有机制是 manifest + `read_skill` 按需拉取，以及 frontmatter `always: true` 全局 eager 注入。落地方案分两档：
   - **短期**：`quant-video-remotion` 技能 frontmatter 置 `always: true`，全局常驻（零开发量，代价是所有会话都带这份上下文）；
   - **中期**：自研"项目级技能挂载"——在 `data/videos/` 项目元数据中声明技能列表，video 系 capability 启动时按声明挂载。列入 §六新增清单；
3. **渲染白名单**：渲染层只认识已注册的场景/布局/组件标识，未知标识渲染降级为占位帧并告警。

新增特效技能（如 three.js）的包结构：

```
skills/three-particle-wave/
├── SKILL.md            # 名称、适用场景、参数 schema、示例 YAML 片段
├── component.tsx       # R3F 场景组件（渲染层注册用）
├── preview.png         # 选择器里的缩略图
└── defaults.json       # 默认参数
```

SKILL.md 片段：

```markdown
---
name: three/particle-wave
description: 粒子波浪背景，适合科技风开场与转场
params:
  count: { type: int, default: 5000, max: 20000 }
  color: { type: color_token, default: primary }   # 仅枚举，禁裸 hex
  amplitude: { type: float, default: 1.0 }
---
当用户要求"科技感开场""粒子背景"时使用本技能，
作为开场屏的视觉增强，duration 建议 3–6 秒。
```

> 注意：特效技能的参数同样遵守色卡规范——颜色参数只接受 7 个枚举 token，与 DSL 全局约束一致。

## 七、数据模型与目录结构

```
data/
├── videos/<series_slug>_ep<NN>.yaml   # 视频描述文件（唯一事实源，YAML）
├── videos/<series_slug>_ep<NN>/       # 该视频配套产物目录
│   ├── data/                          # 图表 CSV/JSON（DSL `data:` 外链相对此解析）
│   ├── assets/                        # imagegen 插画 + .meta.json（生成参数）
│   ├── audio/s<NN>.wav                # 逐屏 TTS 音频 + .align.json（词级时间戳 + 真实时长）
│   └── renders/<job_id>.mp4           # 渲染产物
├── skills/<name>/                     # 安装的技能包（含 quant-video-remotion）
└── user/settings/                     # 沿用 DeepTutor 配置层
```

要点（v1.3 统一口径）：

- 描述文件**只有 YAML 一种格式**，没有 spec.json；目录**只有 `data/videos/`**，没有 `projects/`；
- YAML 是创作层事实源，**运行期产物（真实时长、词级时间戳）一律落在产物目录的 `.align.json`**，由渲染层 IR 注入期读取覆盖，不回写 YAML；
- 渲染任务：`job = {id, yaml_path, yaml_hash, frames, status, progress}`，存 SQLite（沿用 DeepTutor 的会话存储模式，`deeptutor/services/session/sqlite_store.py`）；
- 描述文件的版本管理直接复用 git（YAML 纯文本，diff 友好）或文件快照。

## 十二、与既有视频能力的分工（v1.3 新增）

DeepTutor 已有两个视频/动画相关 capability，本系统与它们**并存、不替代**：

| 能力 | 定位 | 渲染栈 | 适用场景 |
|---|---|---|---|
| `visualize` / `math_animator`（既有） | **即兴可视化**：对话中随手生成图解、数学动画 | Manim / SVG / Chart.js / Mermaid | 单图、短动画、教学答疑中的即时演示 |
| 本系统（video_* 五 capability） | **制片级视频**：多分镜、配音字幕、风格一致的完整作品 | Remotion | 系列课程、科普视频、可精修可重渲染的正式内容 |

边界原则：Manim 能力保持原样、不裁剪（用户对话中的即兴可视化仍走它）；本系统不引入 Manim 依赖。两者产出物形态不同（即时片段 vs 工程化项目），无功能重叠冲突。
